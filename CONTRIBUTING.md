# Contributing

## Setup

Needs [uv](https://docs.astral.sh/uv/) and [just](https://github.com/casey/just);
[pipx](https://pipx.pypa.io/) for installing the command, gitleaks and pre-commit for the hook.

```sh
uv sync                 # create .venv with the dev dependencies
pre-commit install      # gitleaks on every commit
just test               # pytest
just lint               # ruff check + format check (what CI runs)
just fmt                # format and apply safe fixes
just install-dev        # editable pipx install of `amontillado` / `amo`
```

## Coding standards

Tooling enforces what it can (ruff's rule set and line length are in `pyproject.toml`); the rest
is here.

- **Python 3.10+.** `from __future__ import annotations` first in every module; PEP 604 unions
  (`int | None`) and built-in generics (`list[str]`). Type hints on every function signature.
- **`pathlib.Path`**, not `os.path` string handling.
- **CLI:** argparse only (no click or typer), with the shared `HelpFormatter` in `cli.py`; every
  command keeps `--loglevel`. State-changing commands get a `--dry-run`.
- **Output:** data goes to stdout with `print`; diagnostics go to stderr through `logging`
  (Rich handler, set up once in `cli.main`). Never mix the two: `amo list` output is piped.
- **Errors:** expected failures end with `sys.exit("amontillado: <message>")` (lowercase, no
  trailing period); tracebacks are for bugs. Never swallow an exception: log it, re-raise it, or
  exit.
- **No hard-coded paths, hosts or credentials.** Paths come from XDG variables, the config file
  or arguments. The Wallhaven API key comes from the environment or a configured command, and is
  never logged.
- **Structured formats through their parsers:** `yaml.safe_load` only, stdlib `json`, `sqlite3`
  with parameters (never string-built SQL).
- **Subprocesses** with an argument list, `text=True`, and an explicit `check=`.
- **Comments** say why, not what; docstrings carry the reference documentation.
- **No speculative code:** no flags, hooks or modules without a current caller.

## Tests

- `pytest`, no network: the HTTP layer is stubbed with recorded responses in `tests/fixtures/`.
- Test images are generated by the tests; never commit images (`.gitignore` blocks them).
- A test written for a bug must fail without the fix and pass with it.

## Commits

- [Conventional Commits](https://www.conventionalcommits.org/): `<type>(<scope>): <description>`,
  for example `feat(metrics): add hue spread`.
- One logical change per commit; a feature lands layer by layer (metrics, then storage, then the
  command), each with its tests.
- Feature branches for anything bigger than a small fix; `main` stays releasable.
- Update `CHANGELOG.md` under `[Unreleased]` in the same commit as a user-visible change, and
  `docs/design.md` when a design decision or a documented value changes.

## Releases

[Semantic Versioning](https://semver.org/). To release: move the `[Unreleased]` entries under the
new version in `CHANGELOG.md`, set `version` in `pyproject.toml`, commit, and tag `vX.Y.Z` on
that commit. Installs pin a tag: `pipx install git+https://github.com/antimike/amontillado@vX.Y.Z`.
